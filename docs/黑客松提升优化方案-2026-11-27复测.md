## 3. 已经可以保留的部分

这些不用推倒重来。

- 零密钥演练是脚本化的 `normalize_repair`：第一次原样返回输入，真实断言失败，反馈落盘后第二次写成 `'-'.join(value.lower().split())`。审查只做 AST 比对，不执行这份源码。人工批准仍是必经步骤。
- 命令行 `--lang en` 能把帮助、诊断和等待审批说明打成英文。退出码 11 在英文 README 里已有解释。
- 重定向到非 UTF-8 管道时，`doctor` 不再因为中文崩溃。
- 演练项目的竞技场入口会拒绝启动本机真实 CLI。圆桌仍要求配置里有 `openai_compat` 或 `cli_agy`，所以零密钥演练里看不到圆桌。这是安全边界，演示脚本里不要把它说成「当前页面就能会诊」。
- `.kiro/specs/` 已有引擎、证据、适配器和工作台的 requirements / design / tasks。hook 命令已经指向 `verify_judge_demo.py`。IDE 里是否真的触发，还没有屏幕记录。
