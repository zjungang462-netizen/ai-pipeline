## 二、G2 修复空转（阻断级，需重做）

现象：适配器在工作区**外**写 `escaped.txt`，同时正常写 `ok.py` 并声明 `changed_files`。
实测：`{'s1': 'done'}`，状态 DONE，无错误，越界文件确实落盘。

根因在 `safety.py`：

```python
def snapshot(self) -> set[str]:
    for root in self.roots:            # 只遍历可写根
        for p in root.rglob("*"):      # 根外的文件根本不会被扫到
            out.add(str(p.resolve()))
```

`before` 与 `after` 两个集合**只可能包含根内文件**，所以 `after - before` 必然也在根内，`diff_outside` 里那句 `not self.is_inside(f)` 永远为假 —— 函数恒返回 `[]`。

单独验证：`before=0, after=1`（只多了根内 `in.txt`），根外 `escaped.txt` 不在快照里，`diff_outside` 返回 `[]`。

为什么 83 个测试没抓到：G2 的 3 个回归用例大概率是**直接构造 after 集合**塞一个根外路径去调 `diff_outside`，那当然能过；但它们没走 `snapshot()` 的真实产出，也就没覆盖这个盲区。这正是"测试绿、功能假"的典型形态。

修法（任选其一，第二个更实用）：

1. 监视域放大到 `task_workdir.parent`（或配置 `watch_root`）：快照父目录，再做差集，把"新增但不在任何可写根内"的判越界。
2. 在引擎里记录执行前后**父目录**的直接子项条目数 + mtime（廉价启发），只对"新增条目"做完整判定。
3. 明确承认边界：任何快照式方案都抓不到"写到别的盘"，需要在文档里写清"MVP 的越界检测覆盖邻近目录，不做全盘审计"。

另外，`WriteRootGuard.check(workdir)` 只在执行前校验工作目录本身，对适配器运行期间的行为没有约束力 —— 真正的约束只能靠事后检测，所以这个检测不能再是空的。

## 三、裸 JSON 丢问题清单（重要）

| 输入 | 解析结果 |
|---|---|
| 围栏 JSON + 嵌套 issues | `fail`，issues=`['a.py: 空指针（期望: 判空）']` ✅ |
| 裸 JSON + 嵌套 issues | `fail`，**issues=[]** ⚠️ |
| 裸 JSON + 字符串数组 | `fail`，issues=`['缺少边界处理','未补测试']` ✅ |
| verdict=pass 但列 blocker | 正确翻成 `fail` ✅ |
| 含糊中文 | `None`（转人工）✅ |
| 明确"不通过" | `fail` ✅ |

原因：`_BARE_OBJ = re.compile(r"\{[^{}]*\"verdict\"[^{}]*\}")` 不允许嵌套括号，对象数组形式的 issues 匹配失败，退化到关键词判定 —— 结论对了，但问题清单全丢，`format_feedback` 只能写"审查未给出具体问题清单，请全面自查"。

修法：不要用正则找 JSON。先 `text.find("{")`，再用 `json.JSONDecoder().raw_decode` 从该位置解析，失败则挪到下一个 `{` 重试；嵌套问题自然解决。
