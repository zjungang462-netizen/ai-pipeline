## R1（中）Windows 保留设备名导致整批代码文件丢失

**位置**：`orchestrator/adapters/openai_compat.py` `_write_code_files`（约 241-260 行）+ `safety.py` `relative_target`。

**机制**：路径校验拒绝 `..`/绝对路径/盘符/ADS/`.git`，但**不拒绝 Windows 保留设备名**（CON、PRN、AUX、NUL、COM1-9、LPT1-9）。这些名字能通过 `relative_target`，但 Windows 拒绝向 `workdir/CON` 写文件，`write_text` 抛 OSError。异常冒泡到 `run()` 的产物处理 try/except，整个结果被标 `PARSE_FAILED`。

**实测**（探针复现）：
```
输入两个代码块：# file: CON 和 # file: ok.py
结果：written: []，ok.py exists: False
```
即**一个坏文件名连带合法文件全部丢失**，阶段判失败。模型偶尔会生成 `CON`/`aux.py` 这类名字（尤其测试辅助文件），触发即整轮编码白跑。

**建议**：`relative_target` 或 `_write_code_files` 增加保留名检查（Windows 下按不区分大小写匹配设备名基名），命中时降级为默认文件名而非让异常冒泡；或至少逐块隔离失败，不牵连其他块。

## R2（中·测试）中文 Windows 下测试未指定编码，2 个错误

**位置**：
- `tests/test_execution_integrity.py:132`：`decision.json` 用 `read_text()` 无 encoding。
- `tests/test_supervisor.py:49`：`state.json` 用 `read_text()` 无 encoding。

**机制**：产品代码写 JSON 一律 UTF-8（已核实产品代码无裸 `read_text()`），但这两处测试用系统默认编码（中文 Windows = GBK）读含中文的 JSON，抛 `UnicodeDecodeError: 'gbk' codec can't decode byte`。

**实测**：全量测试中这两个用例稳定报错，其余 239 通过。

**建议**：两处补 `encoding="utf-8"`。另有多处测试 `write_text`/`read_text` 未指定编码但内容纯 ASCII 暂不触发（如 test_text_patch.py、test_autotune.py），建议一并规范，避免将来加入中文内容时再炸。

## R3（低·已知未修）返工上下文无文件树，"两套实现并存"根因仍在

**位置**：`engine.py` `_rework_context`（223-255 行）。

**实测**：源码中无 `rglob/iterdir/listdir/文件树` 任何字样——返工只注入被点名文件内容，模型看不到工作区完整文件清单。

**影响**：上一轮真跑（pipe-1）已证实后果：第二轮返工不知道旧包 `todo/todoapp/` 存在，另起一套平铺实现，审查员抓出"两套实现并存"。此问题当时已报告，本轮确认**仍未修**。

**建议**：返工上下文附一份轻量文件树（相对路径清单，很小），并在提示词中明确"修复时删除被取代的旧实现"。

## R4（低）测试阶段 worktree 失败被归入"预算拒绝"事件

**位置**：`engine.py:531-532`：`except artifacts.GitError → self._reject_budget(spec, error)`。

**影响**：阶段判 FAILED 本身正确，但事件类型是 `rejected`（预算语义），git 故障被误标为预算问题，排障时误导。建议单独事件类型（如 `worktree_error`）。

## R5（低）`load_verdict` 的 workdir 缺省退到 cwd

**位置**：`review.py:88,112`。

**实测**：不传 workdir 时按 `Path.cwd()` 校验 issue 路径。引擎唯一调用点（engine.py:864）正确传入 `task_workdir`，**产品无实际影响**；但 API 层面缺省值不安全，未来调用方漏传会用错基准。建议缺省改为抛错或必填。

## R6（低·设计取舍）pass 带任何 issues 一律拒收

**位置**：`review.py:116-117`。

**实测**：`verdict=pass` + 非阻断建议（如"建议优化命名"）→ VerdictError → 待人工确认。
这是"不替模型猜"的保守策略，方向正确，但意味着**审查模型必须学会"pass 时 issues 留空、建议写进报告正文"**，否则频繁卡人工。提示词已有此约定，属可接受的取舍，记录备查。
