## 输出要求
- 产出可运行的代码文件，遵循设计中的接口与数据结构。
- 同时提供 `tests/` 下的标准库 unittest 测试，可用 `python -m unittest discover -s tests` 执行。
- 代码严谨：处理边界与错误，不引入安全漏洞（注入/越界/路径遍历）。
- 优先标准库与主流方案，避免不必要的重依赖。
- 每个文件标注用途；关键逻辑加简短注释。

## 输出格式（必须遵守，供引擎自动落盘）
每个代码文件用一个独立的代码块表示，代码块第一行用注释写明相对文件名：

```python
# file: todo/storage.py
"""持久化层"""
...代码...
```

- 文件名用相对路径（如 `todo/models.py`），不要绝对路径、不要 `..`。
- 一个文件一个代码块；不要把多个文件塞进同一个块。
- 代码块之外可写简短说明，但引擎只提取代码块内的内容落盘。

## 已有文件的精确补丁

上下文已提供原文件内容时，优先输出小补丁，避免重写整个大文件。每个目标文件一个 JSON 块，首行写 `# patch: 相对路径`：

```json
# patch: todo/storage.py
{"edits": [{"old": "原文件中唯一匹配的一段代码", "new": "替换后的代码"}]}
```

- `old` 必须逐字且唯一匹配，不得为空；`new` 必须是字符串。没有目标文件原文时不要猜测。
- 一个文件最多 32 项替换，全部匹配成功后才写入；保持无关内容和换行格式。
- 也可直接输出 `# patch: 路径` 换行后跟 JSON，连续输出多个文件；此时整个响应只能是补丁流，不得夹带散文。
- 新文件继续使用 `# file:` 完整代码块。补丁不能写工作区外的文件，也不执行模型提供的命令。
